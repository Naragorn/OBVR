# The inventory's paperdoll at its size with each thing the figure can carry
# (Nadi, 2026-10-25, of the Windows game of 2026-10-24: "Der 2d Inventar
# player body ist ... irgendwann bugged out worden, war dann extrem
# vergrößert sodass man gar nichts mehr sah"). The fit (render/MenuModelFit.h)
# stands the figure by the view's y scale, which every model draw inside the
# 2D pass hands it from its vertex shader's c1.z, and by the model's world
# bound. The inventory is opened on Tab with the Iron Longsword (00000C0C)
# sheathed, then drawn, then with Torch02 (0002CF9F) in the left hand, then
# with the Arena Iron Shield (000733ED) instead; the lines "the view's y scale
# read as" and "the fit stands the figure" say which draw gave which scale and
# where the figure went, the pictures at the inv- marks how big it is.
# Measured 2026-10-25 20:07 with c1.z as the scale: in one frame the body read
# 4.229 and two pieces of the sheathed sword 0.075 and 0.027 - the last draw
# decided, and at 0.027 the figure would stand 2.6 units from the camera
# instead of 405. Read as the y row's length over the w row's
# (MenuViewYScaleFromRows) every piece reads 4.229, so no line may read less
# than 1.
# Since 2026-10-26 the piece reaching farthest is named when the model's
# bound grows by more than 30 % (Nadi's log of 2026-10-25 21:17: 97.9 to up
# to 878 for single frames) and once at the first read; this run has to
# name the baseline, which walks the model's tree.
# Run with: python3 tools/hand-script-run.py tools/hand-scripts/paperdoll-size.txt --run-timeout 240 --headless
